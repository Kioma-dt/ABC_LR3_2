# Лабораторная работа 3 — Многозадачность в защищённом режиме

Три задачи выполняются по очереди: 1 → 2 → 3 → 1. Переключение аппаратное,
через 32-битные TSS и `JMP FAR`. Передача управления кооперативная: каждая
задача сама выбирает момент переключения. Прерывание таймера не используется.

## Файлы

- `boot.asm` — загрузочный сектор, считывающий основную программу с floppy.
- `main.asm` — переход в защищённый режим, GDT, TSS, задачи и экранный вывод.
- `build.sh` — сборка и создание образа.
- `run.sh` — запуск образа в QEMU.
- `floppy.img` — готовый загрузочный образ 1,44 МБ.
- `report_lab03.docx` — отчёт без листинга исходного кода.

Это загрузочный raw-образ без файловой системы FAT. Форматировать его или
копировать файлы внутрь через файловый менеджер не требуется.

## Установка инструментов в Linux Mint или Ubuntu

```bash
sudo apt update
sudo apt install nasm qemu-system-x86
```

## Сборка и запуск


Новая версия:
```bash
mkdir -p dosfiles
nasm -f bin main.asm -o dosfiles/MAIN.COM
qemu-system-i386 \
  -accel tcg \
  -m 32M \
  -vga std \
  -cdrom FD14LIVE.iso \
  -drive file=fat:rw:dosfiles,format=raw,if=ide \
  -boot d
```

## Что должно появиться

Надпись `PROTECTED MODE: 3 hardware TSS tasks` и три изменяющихся счётчика:
первая задача прибавляет 1, вторая — 2, третья — 3. Числа шестнадцатеричные:
после 9 идут A, B, C, D, E, F. Сразу после полного прохода трёх задач значения
имеют отношение 1:2:3; во время обновления экрана одна задача может опережать
другую на один проход. При переполнении 32 бит счётчик обнуляется.

Закрой окно QEMU, чтобы завершить работу. Возврат в DOS или реальный режим
не предусмотрен: программа загружается непосредственно BIOS.

## Как устроен код

1. BIOS загружает первый сектор в `0000:7C00`. `boot.asm` читает секторы 2–17
   в память `0000:8000` и передаёт туда управление.
2. `main.asm` включает текстовый режим, заполняет базы трёх TSS-дескрипторов,
   загружает GDT командой `LGDT`, устанавливает `CR0.PE` и делает дальний переход.
3. В 32-битном коде загружаются сегментные регистры, стек и IDT для исключений.
   Обычные аппаратные прерывания запрещены; NMI также отключены.
4. `LTR` связывает уже выполняющийся контекст с `tss1`. Сама эта инструкция
   не загружает регистры задачи, поэтому первая задача запускается обычным
   переходом. Вторая и третья впервые запускаются по EIP из своих TSS.
5. Каждая задача при первом входе задаёт свои значения EBX, ESI, EDX и EBP,
   затем выполняет общий участок `task_loop`. Общий код не означает общий
   контекст: регистры и стек у каждой задачи собственные.
6. `JMP FAR [EBP]` использует шестибайтовый указатель `next1`, `next2` или
   `next3`: 4 байта смещения и 2 байта селектора. Для перехода на TSS смещение
   игнорируется. CPU сохраняет контекст в текущий TSS и загружает следующий.
7. Когда задача снова получает управление, выполнение продолжается с команды
   после `JMP FAR`, а EBX содержит её прежний счётчик.

### Основные структуры

| Структура | Назначение |
|---|---|
| GDT | Нулевой дескриптор, код, данные и три TSS-дескриптора |
| Селекторы 08h и 10h | Общие сегменты кода и данных с базой 0 |
| Селекторы 18h, 20h, 28h | TSS первой, второй и третьей задач |
| tss1, tss2, tss3 | По 104 байта состояния процессора |
| stack1, stack2, stack3 | По 512 байт собственного стека |
| IDT | 32 шлюза прерывания с общим аварийным обработчиком |
| B8000h | Видеопамять текстового режима |

У TSS-дескриптора лимит 103, потому что предел — последний допустимый индекс,
а размер — 104 байта. Тип `89h` задаёт присутствующий доступный 32-битный TSS.
CPU помечает текущий TSS занятым (`8Bh`); при `JMP` прежняя задача освобождается.
Поэтому можно циклически переключаться, не редактируя бит busy вручную.

TSS содержит EIP, EFLAGS, общие и сегментные регистры, CR3, селектор LDT и
служебные поля. Операции с x87/SSE не используются, их состояние здесь не
сохраняется. Автоматически сохраняется аппаратно определённая часть TSS;
произвольные дополнительные данные ОС процессор не копирует.

Карта I/O отсутствует: её база равна 104 и находится за лимитом TSS. Все задачи
работают на CPL=0 при IOPL=0, поэтому такая настройка **не запрещает им** доступ
к портам: при CPL ≤ IOPL карта не проверяется. Изоляция памяти, LDT и paging
в этой демонстрации не реализованы.

### Что можно менять

- `DELAY` — число итераций задержки. Это не миллисекунды; скорость зависит от
  компьютера и эмуляции. Для более быстрого вывода уменьши значение, но оставь ≥1.
- `mov esi, 1/2/3` в начальных участках задач — шаги счётчиков.
- Строки `task*_msg` — подписи, но при изменении длины префикса нужно поправить
  столбец вывода `2*25` в соответствующей задаче.

Основная программа дополнена нулями до 8192 байт. Если код и данные превысят
этот размер, NASM выдаст ошибку: загрузчик рассчитан ровно на 16 секторов.
Вся используемая память находится ниже 1 МБ, поэтому включать A20 не требуется.

## Проверка

Сборка NASM и запуск QEMU проверены. Через монитор QEMU проверены CR0.PE,
селекторы TR, записи TSS и несколько последовательных состояний видеопамяти.
Счётчики продолжают увеличиваться, а сохранённые EBX, EIP и ESP соответствуют
задачам. Снимок результата включён в отчёт.

Теоретическая основа: предоставленный файл «Теория ПР3.docx»; последовательность
перехода в защищённый режим адаптирована из предоставленного `main.asm`.
