# Лабораторная работа 3 — три задачи в защищённом режиме

Это руководство относится к окончательному `main.asm`, который имеет `org 0x100`, вычисляет базу программы из `CS` и собирается непосредственно в `MAIN.COM`. В истории файлов этот исходник мог называться `main(1).asm`: перед сборкой сохрани его как `main.asm`. Старый вариант с `org 0x8000` сюда не подходит.

Программа запускается из FreeDOS внутри QEMU. Она переводит процессор в 32-разрядный защищённый режим и циклически выполняет три задачи. Контекст переключается аппаратно с помощью TSS и `JMP FAR`; момент переключения выбирает сама задача. Это кооперативная многозадачность. Все задачи используют один процессор последовательно, поэтому одновременного выполнения трёх потоков команд здесь нет.

## 1. Окончательная последовательность компиляции и запуска

Положи `main.asm` и `FD14LIVE.iso` в одну папку и открой в ней терминал Linux. Если инструменты ещё не установлены:

```bash
sudo apt update
sudo apt install nasm qemu-system-x86
```

Затем выполни именно эту последовательность:

```bash
mkdir -p dosfiles
nasm -f bin main.asm -o dosfiles/MAIN.COM
qemu-system-i386 \
  -accel tcg \
  -m 32M \
  -vga std \
  -cdrom FD14LIVE.iso \
  -drive file=fat:rw:dosfiles,format=raw,if=ide \
  -boot d
```

В меню диска выбери запуск Live-среды без установки. Для программы нужна загрузка без EMM386 и других менеджеров, оставляющих процессор в виртуальном режиме 8086. В FreeDOS F5 во время начальной загрузки позволяет пропустить обработку CONFIG.SYS и AUTOEXEC.BAT; нажимать её нужно на этапе старта ядра DOS, а не произвольно после появления приглашения. Названия пунктов меню могут различаться: выбирай обычный запуск DOS без менеджера расширенной памяти.

В командной строке DOS:

```dos
C:
DIR
MAIN.COM
```

`C:` выбирает первый жёсткий диск, которым в данной конфигурации является виртуальный FAT-диск из `dosfiles`. `DIR` позволяет убедиться, что программа видна. `MAIN.COM` запускает её. Если при другой конфигурации дисков программа оказалась под иной буквой, выбери соответствующий диск.

После запуска появятся три растущих счётчика. Числа шестнадцатеричные: после 9 идут A, B, C, D, E, F. Первая задача прибавляет 1, вторая — 2, третья — 3. Закрой QEMU для завершения: возврат в DOS не реализован.

Перед повторной компиляцией закрой QEMU, затем снова выполни команду NASM и команду QEMU. Не меняй содержимое `dosfiles` одновременно с работой виртуального FAT-диска.

## 2. Что делает программа в целом

1. DOS загружает COM и начинает выполнение в реальном режиме.
2. Программа настраивает сегменты и временный стек, проверяет CR0.PE.
3. BIOS включает текстовый режим VGA 80 × 25.
4. Программа вычисляет физическую базу своего сегмента и исправляет адреса в GDT, GDTR и IDTR.
5. Запрещаются обычные аппаратные прерывания и NMI; загружается GDT.
6. Устанавливается CR0.PE и выполняется дальний переход в 32-разрядный сегмент.
7. Настраиваются сегменты, первый стек, IDT и надписи на экране.
8. `LTR` связывает текущий контекст с первым TSS; обычный переход запускает первую задачу.
9. Задачи по очереди увеличивают счётчик, выводят число, выполняют задержку и переходят на следующий TSS.

Порядок: задача 1 → задача 2 → задача 3 → задача 1. CPU сохраняет состояние предыдущей задачи и восстанавливает следующую. При возвращении задача продолжает выполнение после своего `JMP FAR`, а не запускает инициализацию повторно.

## 3. Обозначения и адресация

### Регистры

`EAX`, `EBX`, `ECX`, `EDX`, `ESI`, `EDI`, `EBP`, `ESP` — 32-разрядные общие регистры. `AX` — младшие 16 бит EAX; `AH` и `AL` — старший и младший байты AX. Аналогично DX состоит из DH и DL. Запись в AX не обнуляет автоматически старшую половину EAX; поэтому для расширения AX используется `MOVZX`.

`CS` задаёт сегмент кода; `DS` — основной сегмент данных; `SS` — стек; `ES`, `FS`, `GS` — дополнительные сегменты. `EIP` — смещение следующей инструкции; `EFLAGS` — флаги. В реальном режиме обычный стек адресуется через SS:SP, а после настройки 32-разрядного стека — SS:ESP.

В программе EBX хранит счётчик задачи, ESI — её шаг, EDX — адрес цифр в видеопамяти, EBP — адрес указателя на следующий TSS. Внутри функций некоторые значения временно используются иначе.

### Скобки и значения меток

`mov eax, tss1` помещает числовое смещение метки в EAX. `mov eax, [tss1]` прочитал бы четыре байта по этому адресу — это другая операция. `mov [gdtr+2], eax` записывает EAX в память. Метка сама по себе не является переменной-указателем: это имя адреса, известного ассемблеру.

Суффикс `h` и префикс `0x` обозначают шестнадцатеричное число: `100h = 0x100 = 256`. Числа без префикса в этом исходнике десятичные: размер TSS 104 байта, предел 103.

### Реальный режим и COM

DOS создаёт PSP — служебный блок размером 256 байт, а машинный код COM размещает со смещения `0100h` в сегменте программы. `org 0x100` заставляет NASM вычислять метки с учётом этого смещения. Директива не вставляет в файл 256 нулевых байт и не переводит CPU в какой-либо режим.

В реальном режиме линейный адрес получается как `segment × 16 + offset`. Если DOS назначила CS=2000h, база программы равна 20000h. Метка со смещением 0500h находится по адресу 20500h. Поэтому нельзя заранее записать в дескрипторы фиксированную физическую базу программы.

В защищённом режиме значение сегментного регистра — селектор дескриптора. CPU берёт базу и предел из дескриптора, затем прибавляет смещение. В этой программе paging выключен, поэтому полученный линейный адрес совпадает с физическим.

Код и обычные данные имеют базу `CS_реального_режима << 4`. Благодаря этому смещения меток остаются пригодными после перехода. Сегмент SEL_FLAT имеет базу 0: через него адрес B8000h действительно обращается к видеопамяти, а не к `база_программы + B8000h`.

## 4. GDT и селекторы

GDT — глобальная таблица дескрипторов. Обычный дескриптор занимает 8 байт. Селектор содержит индекс в таблице, бит TI и уровень RPL. Во всех константах ниже TI=0, то есть выбрана GDT, и RPL=0.

| Индекс | Селектор | Запись GDT | Назначение |
|---|---|---|---|
| 0 | 00h | `dq 0` | Нулевой дескриптор, не рабочий сегмент. |
| 1 | 08h | Код | База программы, 32-разрядные инструкции. |
| 2 | 10h | Данные | База программы, данные и стеки. |
| 3 | 18h | TSS1 | Состояние первой задачи. |
| 4 | 20h | TSS2 | Состояние второй задачи. |
| 5 | 28h | TSS3 | Состояние третьей задачи. |
| 6 | 30h | Плоские данные | База 0, доступ к VGA через ES и GS. |

Формула селектора в данном случае — `индекс × 8`. Например, 3 × 8 = 18h. Селектор не равен физическому адресу TSS: он выбирает дескриптор, содержащий этот адрес.

### Поля восьмибайтового дескриптора

| Смещение | Содержимое |
|---|---|
| +0, 2 байта | Младшие 16 бит предела. |
| +2, 2 байта | База, биты 0–15. |
| +4, 1 байт | База, биты 16–23. |
| +5, 1 байт | Доступ: присутствие, DPL, тип и другие признаки. |
| +6, 1 байт | Старшие 4 бита предела и флаги G, D/B и др. |
| +7, 1 байт | База, биты 24–31. |

`0x00CF9A000000FFFF` задаёт присутствующий исполняемый и читаемый сегмент кода, DPL=0, D=1 и G=1. `0x00CF92000000FFFF` — присутствующий записываемый сегмент данных, DPL=0, B=1, G=1. Начальная база обоих значений равна нулю; для кода и основных данных её исправляет программа. Последний плоский дескриптор остаётся с нулевой базой.

Предел имеет 20 бит и равен FFFFFh. При G=1 он измеряется блоками по 4096 байт: итоговый предел FFFFFFFFh. Это диапазон смещений 4 ГиБ, а не реально выделенная программе память. Широкие сегменты здесь упрощают учебный пример и не обеспечивают изоляцию задач.

Дескрипторы TSS имеют предел 103, G=0 и байт доступа 89h. Размер TSS — 104 байта, поэтому последний допустимый индекс — 103. В 89h установлено присутствие, DPL=0, S=0 (системный дескриптор), тип=9 (доступный 32-битный TSS). При активности CPU меняет тип на Bh, то есть байт доступа становится 8Bh.

GDTR — регистр с пределом и линейной базой GDT. Структура `gdtr` в памяти содержит два байта предела и четыре байта базы. GDT имеет 7 × 8 = 56 байт, поэтому предел равен 55. IDTR устроен аналогично, но относится к таблице прерываний.

## 5. Подготовка и включение защищённого режима

`CLI` очищает IF и запрещает обычные маскируемые аппаратные прерывания. Он не запрещает программные инструкции INT, процессорные исключения и NMI. Поэтому BIOS INT 10h работает и после CLI.

CS уже назначен DOS. Копирование CS в DS, ES и SS устанавливает общую базу кода, данных и временного стека. SP=7C00h — выбранное смещение вершины временного стека внутри сегмента COM; это не физический адрес загрузочного сектора 0000:7C00. Стек используется командами CALL, RET и BIOS до перехода в защищённый режим. Такая организация предполагает обычное выделение DOS памяти для COM, достаточное для этого смещения.

CLD очищает DF. Строковые команды после этого двигают указатели к большим адресам. Без этого оставленный DF=1 заставил бы LODSB/STOSW идти назад.

SMSW получает младшую часть машинного слова состояния, включая PE. TEST проверяет бит 0, не меняя AX. Если PE уже равен 1, JNZ переводит управление к сообщению об ошибке. В виртуальном режиме 8086 программа не должна сама менять CR0 и таблицы ОС. Эта проверка предназначена для обычного DOS-окружения; она не является универсальным определением всех виртуальных машин и менеджеров памяти.

AX=0003h и INT 10h вызывают BIOS: AH=00h — установить видеорежим, AL=03h — цветной текстовый режим 80 × 25. После BIOS повторно устанавливаются DS и ES и выполняется CLI.

MOVZX EBX,AX получает 32-битное беззнаковое значение сегмента, а SHL EBX,4 умножает его на 16. EBX теперь содержит линейную базу программы. Для двух обычных дескрипторов передаётся сама эта база; для TSS — база плюс смещение соответствующей метки.

`set_tss_base` называется по назначению TSS, но формат поля базы одинаков и у обычных сегментов. Поэтому функция также исправляет дескрипторы кода и данных. Вход: EAX — база, DI — смещение дескриптора. Запись AX в +2 сохраняет младшие 16 бит. После SHR EAX,16 байт AL содержит исходные биты 16–23, а AH — 24–31. Они записываются в +4 и +7. Функция разрушает EAX, но сохраняет EBX, поэтому перед каждым вызовом EAX заполняется снова.

Базы в GDTR и IDTR — линейные адреса самих таблиц. Они не интерпретируются относительно DS после загрузки в CPU. Поэтому к меткам `gdt` и `idt` также прибавляется EBX. Значение `dd gdt`, помещённое NASM в файл, до такого исправления является только смещением.

Вывод 80h в порт 70h устанавливает бит запрета NMI и одновременно выбирает индекс CMOS 0. Это отдельная операция от CLI. Восстановление NMI не выполняется, поскольку программа не возвращается в DOS. LGDT загружает GDTR, но сам ещё не переключает режим CPU.

Чтение CR0 в EAX, установка бита через OR и запись обратно сохраняют остальные биты CR0. Устанавливается PE; paging этим не включается. Дальний JMP загружает CS=08h и EIP=pm_entry. Новый дескриптор кода имеет D=1, поэтому CPU использует 32-разрядные размеры по умолчанию. `dword` в инструкции задаёт 32-битное поле смещения дальнего перехода. Директива `bits 32` лишь сообщает NASM, как кодировать последующие инструкции; переключение процессора делают CR0 и дальний JMP.

После перехода DS, FS и SS получают SEL_DATA. ES сначала также получает SEL_DATA, но затем перезаписывается SEL_FLAT; промежуточная загрузка ES здесь избыточна. GS тоже получает SEL_FLAT. ESP устанавливается на stack1_top. После смены SS нельзя продолжать пользоваться случайным старым ESP: нужна явная вершина нового стека.

## 6. Таблица исключений IDT

Программа создаёт 32 записи — для векторов 0–31. Все ведут на `exception_stop`. Это шлюзы прерывания в сегменте кода, а не шлюзы задач. IDT не осуществляет переключение трёх рабочих задач.

В каждой итерации EDI указывает на очередные 8 байт IDT, EAX содержит смещение обработчика в сегменте кода. Младшие 16 бит адреса пишутся в +0; селектор кода — в +2. Значение 8E00h записывается в +4: в little-endian нулевой резервный байт оказывается в +4, а атрибуты 8Eh — в +5. У 8Eh P=1, DPL=0, тип Eh — 32-битный interrupt gate. Старшие 16 бит смещения обработчика пишутся в +6.

EDX служит временной копией EAX: сдвигать сам EAX нельзя, иначе следующая итерация потеряет полный адрес. EDI увеличивается на 8; LOOP уменьшает ECX и повторяет цикл до нуля. LIDT загружает готовую таблицу. Её размер 32 × 8 = 256 байт, предел 255.

Сразу после включения PE и до LIDT существует короткий участок без настроенной защищённой IDT. В нём IF=0 и NMI запрещены, но исключение из-за ошибки настройки всё равно было бы опасно. Это учебная программа, а не полноценное ядро с отказоустойчивой ранней обработкой исключений.

## 7. Задачи и аппаратное переключение

### Первый запуск

LTR принимает SEL_TSS1 и загружает регистр задачи TR, отмечая TSS1 занятым. LTR не читает из TSS1 EIP, ESP и остальные регистры для запуска. Поэтому первый стек уже настроен в pm_entry, а первая задача начинается обычным `jmp task1`.

При первом переходе во вторую задачу процессор читает её начальные EIP, ESP и сегменты из tss2. Аналогично впервые стартует третья задача. Поля tss1 для начального запуска фактически не используются: при первом уходе из первой задачи CPU запишет туда её реальное состояние.

### Собственное состояние при общем коде

| Задача | EBX при старте | ESI, шаг | EDX, позиция | EBP, следующий указатель |
|---|---|---|---|---|
| 1 | 0 | 1 | Строка 3, столбец 25 | next2 |
| 2 | 0 | 2 | Строка 5, столбец 25 | next3 |
| 3 | 0 | 3 | Строка 7, столбец 25 | next1 |

Номера строк и столбцов отсчитываются от нуля. `xor ebx,ebx` обнуляет счётчик, выполняя побитовое XOR регистра с самим собой. Инициализация выполняется только при первом входе в task1/task2/task3. Возвращение из другой задачи происходит ниже, после сохранённого JMP FAR.

Общий участок task_loop не делает состояние общим. Это один набор инструкций, исполняемый с разными регистровыми контекстами и стеками. По смыслу несколько потоков также могут выполнять одну функцию, не разделяя свои регистры и локальные стеки.

`add ebx,esi` увеличивает счётчик. После вывода ECX получает DELAY. Команда LOOP декрементирует ECX и переходит назад, пока он не ноль; арифметические флаги эта инструкция не изменяет. 3000000 — число итераций, не время в миллисекундах. Здесь нет ожидания таймера и HLT между итерациями: CPU занят циклом. Значение DELAY должно быть положительным; при исходном нуле LOOP сначала получит FFFFFFFFh и выполнит огромную задержку.

### Что означает JMP FAR [EBP]

В `next1`, `next2`, `next3` лежат шестибайтовые дальние указатели: четыре байта смещения, затем два байта селектора. EBP хранит смещение одного из этих указателей. Скобки заставляют CPU прочитать содержимое памяти. Это не непосредственный переход по числу, лежащему в EBP.

Особенность x86: адресация с EBP по умолчанию использует SS, а не DS. Здесь у SS и DS одинаковые селектор и база, поэтому `jmp far [ebp]` корректно читает указатель из сегмента программы. Остальная обычная адресация с EDI и EBX в этом исходнике использует DS, если явно не указан другой сегмент.

Селектор из указателя выбирает системный дескриптор TSS. Поэтому CPU выполняет переключение задачи, а не обычную загрузку другого CS. Нулевое поле смещения в таком переходе игнорируется: начальный или сохранённый EIP берётся из TSS.

Упрощённая последовательность аппаратного переключения:

1. CPU проверяет целевой дескриптор, присутствие, допустимость и состояние TSS.
2. Сохраняет в текущий TSS регистры, флаги, EIP продолжения и другие предусмотренные архитектурой поля.
3. При JMP снимает busy с предыдущего TSS и устанавливает busy у следующего.
4. Обновляет TR и загружает контекст следующей задачи, включая EIP, EFLAGS, ESP, общие и сегментные регистры; обрабатывает CR3 и LDT в соответствии с механизмом переключения.
5. Продолжает выполнение новой задачи по её EIP.

При следующем выборе прежней задачи её EIP указывает на `jmp task_loop`, расположенный непосредственно после `jmp far [ebp]`. Поэтому счётчик не обнуляется и повторяется следующий проход.

CALL на TSS или шлюз задачи мог бы создать вложенную задачу с backlink и NT. Здесь используется JMP: вложенная цепочка возвратов не создаётся, NT остаётся 0. IRET для возврата между рабочими задачами не нужен. На занятый TSS обычным JMP переходить нельзя; корректность кольца обеспечивается снятием busy при предыдущем уходе. Ручное редактирование busy не требуется.

Переключение устанавливает CR0.TS. Это связано с обработкой состояния сопроцессора. Программа не выполняет x87/SSE, поэтому не реализует ленивое сохранение их состояния и обработку #NM. TSS не сохраняет автоматически регистры FPU/SIMD или произвольные дополнительные данные, дописанные ОС за стандартной структурой.

### Пример состояния

После первого полного круга счётчики равны 1, 2 и 3; после второго — 2, 4 и 6. Во время обновления экран может показывать, например, уже обновлённую первую строку и ещё прежние вторую и третью. Это нормально: задачи выполняются последовательно. При переполнении EBX арифметика идёт по модулю 2^32; отдельной обработки переноса нет.

Если одна задача перестанет доходить до JMP FAR, остальные перестанут получать управление. Именно поэтому этот вариант называется кооперативным. Прерываний таймера, вытесняющего планировщика, приоритетов и квантов времени здесь нет.

## 8. Вывод в VGA

В текстовом режиме экран состоит из 80 × 25 ячеек. Ячейка занимает два байта: код символа и атрибут. Поэтому строка занимает 80 × 2 = 160 байт. Адрес ячейки: `B8000h + строка × 160 + столбец × 2`.

Числа выводятся со столбца 25 после префикса `Task 1  step +1   count: `, состоящего из 25 символов. Изменишь длину префикса — потребуется изменить `2*25` в задаче.

### print_string

На входе ESI — смещение строки внутри сегмента программы, EDI — линейный адрес ячейки VGA. AH=0Fh задаёт ярко-белый символ на чёрном фоне. LODSB читает байт из DS:ESI в AL и увеличивает ESI на 1 при DF=0. TEST AL,AL проверяет нулевой терминатор. Если он встречен, JZ выходит из функции.

STOSW записывает AX в ES:EDI и увеличивает EDI на 2. AL содержит символ, AH — атрибут; порядок little-endian помещает их именно в нужные байты ячейки. ES имеет нулевую базу, поэтому EDI=B8000h означает видеопамять. Обычные данные строки при этом читаются через DS с базой программы.

Функция разрушает AL/AH, ESI и EDI и не сохраняет флаги. На этапе печати заголовков это допустимо: каждый следующий вызов заново задаёт нужные ESI и EDI. В цикле задач используется другая функция с сохранением регистров.

### print_hex32

На входе EBX — число, EDX — адрес первой цифры. PUSHAD кладёт на собственный стек задачи восемь 32-битных общих регистров: EAX, ECX, EDX, EBX, исходное ESP, EBP, ESI и EDI. Это 32 байта. Возвратный адрес, ранее помещённый CALL, занимает ещё 4 байта. PUSHAD не сохраняет EFLAGS и сегментные регистры.

EAX получает копию числа, EDI — экранный адрес, ECX — 8, поскольку 32 бита дают восемь шестнадцатеричных цифр. ROL EAX,4 циклически поворачивает число влево: старшая тетрада оказывается в младших четырёх битах. Для 12345678h после первого ROL получается 23456781h, поэтому первая выделенная цифра — 1.

EBX получает копию повёрнутого EAX. AND EBX,0Fh оставляет индекс 0–15. Чтение `hex_digits+ebx` выбирает символ из строки `0123456789ABCDEF`. В DL помещается символ, в DH — атрибут 0Ah, ярко-зелёный на чёрном фоне. Запись DX в GS:EDI выводит оба байта ячейки. Явный GS нужен, потому что обычный DS имеет ненулевую базу программы.

Цикл повторяется 8 раз, EDI каждый раз увеличивается на 2. После восьми поворотов число в EAX возвращается к исходному расположению битов, хотя для внешнего кода это неважно: POPAD восстанавливает сохранённые общие регистры. POPAD пропускает сохранённый слот ESP, а не загружает из него произвольную вершину стека. RET снимает возвратный адрес, помещённый CALL.

EDX внутри функции используется для пары символ/атрибут, а EBX — для индекса цифры, но после POPAD восстанавливаются исходные экранный адрес и счётчик. Поэтому задача продолжает работу с прежними EBX, ESI, EDX и EBP. Флаги функция не обязана сохранять: код после CALL на них не опирается.

## 9. TSS и макрос TASK_TSS

Макрос — механизм NASM при сборке. Вызовы `TASK_TSS task1, stack1_top` и аналогичные разворачиваются в байты данных. Во время исполнения CPU не вызывает этот макрос как функцию. `%1` означает первый аргумент — начальный EIP; `%2` — второй аргумент, вершину стека.

| Смещение | Поле | Значение в исходнике и смысл |
|---|---|---|
| 00h | Previous task link + резерв | 0, вложенных вызовов задач нет. |
| 04h | ESP0 | `%2`, вершина стека нулевого кольца. |
| 08h | SS0 + резерв | SEL_DATA и нули в верхних 16 битах. |
| 0Ch / 10h | ESP1 / SS1 | 0, переходы в кольцо 1 не используются. |
| 14h / 18h | ESP2 / SS2 | 0, кольцо 2 не используется. |
| 1Ch | CR3 | 0; paging выключен. |
| 20h | EIP | `%1`, начальная метка task1/task2/task3. |
| 24h | EFLAGS | 2: обязательный фиксированный бит 1 установлен; IF=0, DF=0, NT=0, IOPL=0. |
| 28h | EAX | 0 при первом аппаратном запуске. |
| 2Ch | ECX | 0. |
| 30h | EDX | 0; задача позже установит экранный адрес. |
| 34h | EBX | 0; счётчик задачи. |
| 38h | ESP | `%2`, собственный стек текущего уровня. |
| 3Ch | EBP | 0; затем адрес next1/next2/next3. |
| 40h | ESI | 0; затем шаг счётчика. |
| 44h | EDI | 0. |
| 48h | ES + резерв | SEL_FLAT, запись строк в видеопамять. |
| 4Ch | CS + резерв | SEL_CODE, 32-разрядный код программы. |
| 50h | SS + резерв | SEL_DATA, собственный стек. |
| 54h | DS + резерв | SEL_DATA, данные программы. |
| 58h | FS + резерв | SEL_DATA. |
| 5Ch | GS + резерв | SEL_FLAT, запись цифр в видеопамять. |
| 60h | LDT + резерв | 0, локальная таблица отсутствует. |
| 64h | Trap + резерв | 0, отладочная ловушка при переключении не запрашивается. |
| 66h | База I/O bitmap | 104, карта находится за пределом структуры и фактически отсутствует. |

`dd SEL_DATA` в поле сегмента выделяет 4 байта: младшие 16 бит — селектор, старшие 16 — резерв. Поэтому это корректно, хотя сам селектор 16-разрядный. Последняя строка `dw 0,104` задаёт два отдельных двухбайтовых поля. Вся структура занимает ровно 68h = 104 байта.

ESP0/SS0 нужны механизму перехода на более привилегированный стек, например при переходе из пользовательского кольца в ядро. В этой программе задачи всегда работают в CPL=0, так что основным рабочим указателем является обычное поле ESP; заполнение ESP0 не означает автоматическое переключение на него при каждом JMP между задачами.

База I/O bitmap за пределом TSS **не запрещает этим задачам обращаться к портам**. При CPL=0 и IOPL=0 условие CPL ≤ IOPL выполнено и CPU разрешает обычные IN/OUT без проверки bitmap. Эта настройка означала бы отсутствие разрешённых битов карты для тех обращений, при которых проверка карты действительно требуется.

## 10. Исключения, ошибка запуска и завершение

`dos_error` достижим до изменения CR0. STI разрешает маскируемые прерывания, DX получает смещение строки. AH=9 и INT 21h выводят DOS-строку до `$`. В строке 13 — возврат каретки, 10 — перевод строки. AX=4C01h и INT 21h завершают DOS-программу с кодом возврата 1: AH=4Ch — функция завершения, AL=1 — код ошибки.

Обычные экранные строки завершаются нулём, а эта строка — знаком `$`: разные соглашения объясняются разными функциями вывода. В защищённом режиме программа DOS INT 21h и BIOS INT 10h уже не вызывает.

`exception_stop` — общий аварийный обработчик. CLI гарантирует IF=0, CLD задаёт прямое направление строковых операций. Затем выводится сообщение в строке 15, и CPU останавливается HLT. Короткий JMP возвращает к HLT, если выполнение по какой-либо причине возобновилось.

Некоторые исключения помещают в стек дополнительный код ошибки. Здесь обработчик никогда не делает IRET и не возвращается к задаче, поэтому код ошибки не снимается. Номер исключения тоже не выводится: сообщение позволяет увидеть остановку, но не заменяет диагностику. Обработчик предполагает, что DS и ES пригодны для вывода; при тяжёлой ошибке сегментов или стека даже такой обработчик может не сработать.

После успешного запуска нет штатного выхода, восстановления исходных таблиц, NMI и режима CPU. Закрытие QEMU завершает гостевую систему. Внутри лабораторного примера это сознательно упрощает код.

## 11. Статические данные, выравнивание и стеки

`db` размещает байты, `dw` — 16-разрядные слова, `dd` — 32-разрядные значения, `dq` — 64-разрядные значения. Это директивы сборки, а не команды процессора. Несколько значений через запятую размещаются подряд. Числа многобайтных полей записываются в little-endian.

`equ` задаёт числовую константу без выделения памяти. `times N db 0` создаёт N нулевых байт. `align 8, db 0` добавляет от 0 до 7 нулевых байт, чтобы следующая структура имела адрес, кратный 8. Аналогично align 4 и align 16. Это удобное выравнивание, а не исполнение восьми операций и не строго обязательное условие для всех этих структур на x86.

`gdt_end-gdt-1` и `32*8-1` вычисляются NASM при сборке. Они дают последний допустимый байтовый индекс таблиц. Отдельные `gdtr`/`idtr` — структуры в памяти для LGDT/LIDT, а не сами аппаратные регистры.

Три области stack1, stack2, stack3 занимают по 512 байт и включены в COM как нули. Метки stack1_top и т. д. стоят сразу после соответствующих областей. Стек растёт к меньшим адресам: PUSH сначала уменьшает ESP, затем записывает значение. Поэтому вершина задаётся адресом конца области, а не её начала. stack1_top совпадает с началом stack2, что нормально: первый PUSH первой задачи пойдёт в байты ниже этой границы.

Временный стек с SP=7C00h используется только на раннем этапе; рабочие стеки задач — отдельные области в конце исходника. Защиты от переполнения 512-байтового стека нет, а широкий предел сегмента SS не выявит выход из собственной области. Для небольших CALL и PUSHAD в данном примере этого объёма достаточно.

## 13. Что важно уметь объяснить на защите

- Защищённый режим включают установкой PE и дальним переходом; BITS управляет только сборкой.
- GDT описывает сегменты и TSS, а IDT — обработчики исключений. Селектор выбирает запись таблицы.
- TSS — структура состояния; TR определяет текущую задачу. LTR только устанавливает исходную связь.
- Контекст рабочих задач переключает JMP FAR на TSS, а CALL print_hex32 — обычный вызов функции внутри одной задачи.
- У каждой задачи собственные регистры и стек, хотя код, таблицы и адресное пространство общие.
- DELAY — занятое ожидание; никакого таймерного вытеснения здесь нет.
- Видеопамять используется напрямую через сегмент с базой 0; DOS-функции в защищённом режиме не вызываются.
- Отдельные TSS и стеки не дают изоляции памяти. Все задачи привилегированные, имеют доступ к общей памяти и портам.

## 14. Источники и пределы проверки

Разбор привязан к окончательному исходнику COM, прочитанному перед подготовкой этого README. Исходный main.asm в рамках этой задачи не изменялся. Ранее были проверены сборка NASM и выполнение защищённого участка в QEMU с загрузкой COM-кода в сегментную среду; это не следует считать отдельным подтверждением всех пунктов загрузочного меню приложенного ISO. Команды запуска приведены в согласованной пользователем конфигурации FreeDOS.

- [Intel Software Developer’s Manual, том 3A](https://cdrdv2-public.intel.com/835754/253668-sdm-vol-3a.pdf) — защищённый режим, дескрипторы, TSS и переключение задач.
- [NASM, формат bin и COM](https://nasm.us/doc/nasm09.html) — плоский двоичный файл и ORG.
- [NASM, директива BITS](https://nasm.us/doc/nasm08.html) — выбор кодирования инструкций.
- [QEMU, образы дисков](https://www.qemu.org/docs/master/system/images) — виртуальный FAT-диск из каталога хоста.
